Architecture

The model is deterministic and does one job: score abuse probability. The agent reasons over five tools — each backed by a real data source — and decides: approve, flag, or ask for more evidence. Every step is logged.

Solid arrows: control flow. Dashed arrows: data pulled from a real source. Amber: the payment-network signal no single merchant could see on its own.

Three actions, not two

Binary approve/flag forces a call even when evidence is incomplete. A third tier escalates when signals conflict or evidence is missing — instead of guessing.

Cost-optimal threshold, not 0.5 by default

A false positive costs roughly the order value in lost trust. A false negative costs the refund amount. We swept every cutoff and priced both.

Total dollar cost vs. decision threshold, held-out test set (12,000 orders). 0.43 is the center of the safe zone — the robust choice, not the risky edge.

Failure recovery

What actually broke, and what changed because of it.

01

The model scored 1.000 / 1.000 — and that was a red flag, not a win

Investigated feature importances and class distributions before trusting it. Found the benchmark's classes are cleanly separable by construction — reported honestly as a synthetic-data artifact, not a solved-fraud claim.

02

Paid API cost became a real blocker

Pivoted the entire agent runtime to a free local model (Ollama) mid-build, rewriting the tool-calling loop for a different API shape — without losing any of the guardrail logic.

03

A 100-order evaluation got killed at 71/100

Rather than restart blind, wrote a recovery script that reconstructed precision/recall from the partial audit log — 0.958 precision, 1.000 recall stood on real, if incomplete, evidence.

04

The production model was quietly the worst one

A full model comparison showed Random Forest — already shipped — was the least-calibrated of three candidates despite tied accuracy. Swapped it before calling the model "done."
